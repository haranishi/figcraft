## Change design

`Cargo.toml` currently requests zip 2; use zip 9.0.5 with the same `default-features = false` and `deflate` feature selection, then let Cargo update the lockfile.
The major change is required by the shared fix boundary; it is not accepted as compatible merely because the version resolves.
Archive users are crates/format (native, .fig and library data) and the server fixtures. The native TLS path is crates/collab-net/src/tls.rs; raise its rustls minimum within 0.23 and pin the same patch in Cargo.lock.
Use the installed Rust 1.99 toolchain, an isolated official-registry Cargo cache and a bounded temporary target directory. Do not build the full GUI workspace without enough disk space.
Keep application source unchanged unless the ZIP API requires a minimal compatibility adjustment; never remove limits, tests, certificate checks or features to obtain a pass.
ZIP 9 returns fallible names (`ZipResult<Cow<str>>`) from entry/name iterators. Preserve the PPTX reader's existing skip-and-log policy for an unreadable part, reject invalid native-format names as corrupt, and preserve boolean sniffing and synthetic fixture assertions. No limits or certificate checks are relaxed.
